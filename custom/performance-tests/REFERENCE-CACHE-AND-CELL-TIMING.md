# Shared paging reference reads and cell-load diagnostics

The 19:53 capture attributes the ray stall primarily to preparing paged-object chunks. Subcell chunks currently reread and resolve the same whole ESM3 cell before filtering by their own bounds. This change caches the collector output for chunks of size <= 1, per ObjectPaging instance/worldspace, with a 64-cell FIFO limit. Larger/far chunks and ESM4 collection keep the existing path. The same original collector resolves plugin ordering, deletions, moved and leased references; each chunk receives a private map before current blacklist/disabled and position filters run.

Loads for one retained key share a call_once entry; different cells load outside the global cache lock. Clear detaches pending loads and clears the cache, while current readers retain immutable shared ownership. Collector read failures retain existing warning/partial-result behavior but do not publish an incomplete cached value; subsequent requests retry. Entry count is bounded, not byte size. Memory depends on reference density and temporarily retained evicted values.

This is a generic preparation optimization, not spatial ray rejection. The latter remains deferred because terrain-only bounds do not conservatively enclose paged objects. No geometry, ray masks, LOD selection, hit metadata, or occlusion behavior changes. Expected speedup is unmeasured; this does not claim the entire multi-second stall fixed. Existing engine improvements remain included.

New terrain/object scopes: collectReferences, readCellReferences (actual cache misses), getModelTemplate. New scene-cell scopes use cell descriptions and separate terrainPhysics, pathgrid, localScripts, respawn, insertObjects, renderingCell, windowCell, waterAndAmbient, notifyPreloader. InsertObjects contains collectObjects, renderAndPhysicsObjects and navigationObjects. Common object insertion also splits model, rendering, mechanicsAndEffects, physics and luaNotification. Nested timings are inclusive and must not be summed across levels or threads.

Validation: standalone C++20 cache test covers concurrent same-key reuse, different-key progress, immutable/private filtering, FIFO eviction and reader lifetime, failed-load retry, and clear during a blocked load. The test is wired into the Windows pre-build gate. Full engine compilation and existing component/timing tests run in CI. No live OpenMW result yet.
